### Fixes

- Restarting or updating Vorteo is much less likely to sign a Claude subscription account out when the restart lands while the account renews its sign-in. Claude Code holds a lock while it renews, usually for under a second, and a process stopped inside that time could discard the renewed sign-in. Vorteo now waits up to three seconds for that lock to clear before it ends a Claude Code process, whether for a session close, idle cleanup, a session host shutdown, a restarted query or its own short internal sessions.

## Maintenance review

`claudeRenewalInProgress` and `waitForClaudeRenewal` in the Claude provider's `account-starts.ts` read the modification time of the `.oauth_refresh.lock` directory in the account's configuration directory. Claude Code 2.1.321 takes that lock before it sends the renewal token, touches it every five seconds and releases it after saving, so a lock not touched for twelve seconds is treated as abandoned and cannot delay later stops. `closeSession`, the query retire path, the missing resumed conversation path, the query pump's exit and the model discovery probe wait before ending the CLI; the session host's idle close and shutdown are covered because both end a session through its close. The pump waits because leaving it makes the SDK end the process, and the discovery probe now hands the SDK its own abort controller, aborted after the wait, because the SDK ends the process as soon as its controller aborts. The retire path waits before it detaches the query so no second CLI starts beside the first. The wait is three seconds so that it and a graceful stop fit the daemon's five second agent close limit and, after the session host's ten second settle wait and four second kill, its twenty second shutdown deadline. Observed renewals held the lock for 0.6 to 6 seconds on the lab Host on 2026-11-13 and 2026-11-14, so the slowest observed renewal is longer than the wait. Not covered: a renewal slower than three seconds, which logs a warning; `claude auth status` stopped by its five second limit outside the expiry guard; a process killed from outside Vorteo; the SDK's exit hook and the supervisor's forced kill when the daemon or session host exits with a CLI still alive; and a later Claude Code that renames the lock, which would silently disable the wait. This path had not been observed to cause a sign-out: about ten renewal rounds across at least twelve daemon and five session host restarts lost no sign-in, with restarts kept away from renewal times by hand. One test covers the wait, its bound, a session close held by a live lock, and the abandoned lock; it fails when the wait is removed from the session close. The subscription accounts entry in the customizations inventory is updated; that entry appears twice in the inventory after an earlier merge and only the current copy was edited. README overview and onboarding are unchanged. Not installed.
